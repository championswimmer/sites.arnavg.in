Where should an agent run code?

A working comparison of the sandbox platforms that actually matter in 2026 — start time, execution, isolation, persistence, GPU, BYOC, and what you will pay once marketing numbers leave the room.

Eighteen months ago “AI sandbox” meant E2B. Now every hyperscaler, edge network, and PaaS has a product in the category, and a second wave (Sprites, Blaxel, Runloop, Railway Sandboxes, Northflank, Upstash Box) is competing on persistence, idle cost, and the agent loop itself. They look interchangeable on a feature page. They are not.

Claimed ≠ measured

Vendor cold starts are often 5–10× faster than independent create-to-first-exec. Reliability (success rate, P99) beats a 90 ms median that fails two thirds of the time.

Billing is the trap

Wall-clock vs active-CPU vs cgroup-usage vs idle-free hibernation changes the bill more than the sticker rate. A “cheap” vCPU-hour can be the expensive one.

Isolation is a stack

Firecracker is a floor, not a ceiling. DNS, credentials, and network policy are how sandboxes actually get owned — AWS AgentCore already had a public stress-test.

How to read this. Sticker rates are from vendor pages as of May–September 2026. Create/resume timings in the “measured” column are from LogRocket’s August 2026 hands-on (create → exec → pause → resume) and the January 2026 sandbox-comparison.pages.dev run, called out separately. Northflank’s scale-cost tables are theirs; treat them as a directional PaaS ranking, not a quote. Recheck before you sign a contract.

How to pick

The decision is the constraint, not a league table.

UNTRUSTED CODE AT SCALE

E2B

Firecracker microVMs, the category default, 1B+ sandboxes started, pause/resume with memory, Python+TS SDKs. Pro is $150/mo + usage. BYOC exists but is sales-gated.

CODING AGENT, STATEFUL, IDLE-FREE

Fly Sprites

Persistent ext4 on Firecracker, auto-hibernate, ~300 ms checkpoints, network allowlists the guest cannot rewrite. You pay cgroup usage; a sleeping sprite costs storage only. GPU is not here — use Fly Machines.

ALREADY ON VERCEL / NEXT

Vercel Sandbox

Firecracker, persistence-by-default, TypeScript-first, active-CPU billing (I/O wait is free). Measured resume is slow (~3.3 s). iad1-only. No GPU, no BYOC.

ALREADY ON WORKERS

Cloudflare Sandbox

Containers next to Workers, V8 isolates if you can live in Code Mode. Active CPU, $5 Workers Paid floor. Cold container start is seconds, not milliseconds. No GPU in the sandbox.

GPU IN THE BOX

Modal — then Northflank / Daytona

Modal has the deepest serverless GPU catalogue (T4–B200), gVisor isolation, scale-to-zero. Northflank undercuts GPU and CPU on PaaS and is the self-serve BYOC play. Daytona advertises H100 sandboxes and Computer Use.

AGENT NEXT TO THE APP

Railway Sandboxes

Full VMs billed at $50/vCPU-month and $50/GB-month while running. Checkpoints + fork. Optional private-network join to the project’s Postgres/Redis. Default image now ships Claude Code, Codex, Cursor, Droid, OpenCode, Pi. Idle is still billed until destroy/timeout.

FASTEST ADVERTISED CREATE

Daytona, with a caveat

Sub-90 ms is the pitch; LogRocket measured ~742 ms create. CreateOS’s 26-provider run (Aug 2026) saw 0.22 s median and a 37% success rate. Public repo froze June 2026 (last OSS is AGPL v0.190.0). Use the hosted product, not the GitHub star count.

CHEAPEST AT 200 CONCURRENT

Northflank

$0.01667/vCPU-hr on PaaS — roughly 3× cheaper than E2B/Daytona at the published CPU rate — plus self-serve BYOC on AWS/GCP/Azure/Oracle/CoreWeave/bare metal. Isolation is Kata or gVisor per workload.

Isolation is not one knob

Four floors are in production. Stronger isolation costs start time and density. Weaker isolation is how you get 90 ms creates.

FloorWhat it actually meansWho ships itTradeoff
microVMHardware virtualization, own kernel. Firecracker (AWS-born) or libkrun. Guest root is not host root.E2B, Vercel, Sprites, CodeSandbox/Together, AWS AgentCore, Railway VMs, Microsandbox, ZerobootStrongest default for untrusted code. Start time is the tax, unless you snapshot.
gVisorUser-space kernel intercepts syscalls. Not a second kernel; a filter in front of the host kernel.Modal, Google Agent Sandbox / GKE, some Northflank workloadsGood density, GPU-friendly. Weaker than a microVM against kernel bugs.
Kata / SysboxContainer API, VM or user-namespace backend. Daytona’s “opt-in stronger runtime.”Northflank (Kata), Daytona (opt-in), OpenSandbox (pluggable)You have to turn it on. Default Docker is not this.

Isolation is the compute boundary. The 2026 lesson is that network is how you actually lose: researchers showed DNS-exfiltration and credential-extraction paths in AWS’s code-interpreter sandboxes. AWS called the network behaviour intended and published hardening guidance. A Firecracker box with an open resolver is still a mailbox.

Four ways you get billed

Comparing “$/vCPU-hour” without the meter is how people overpay.

  1. Wall-clock while alive. E2B and Daytona charge CPU + RAM for every second the sandbox exists, whether it is computing or waiting on the model. Pause (E2B) stops the meter and keeps state; you pay storage.
  2. Active CPU, provisioned memory. Vercel and Cloudflare bill CPU only when the guest is on-CPU. Memory is provisioned for the whole lifetime. I/O-wait-heavy agent loops get dramatically cheaper. A 100% busy compiler does not.
  3. cgroup actuals, zero idle. Sprites meters cpu.stat and memory.current (with a 6.25% CPU / 250 MB floor per second of runtime). Warm and cold sprites are not billed for compute. Blaxel’s standby is the same idea with memory-tier SKUs.
  4. Running VM, including idle. Railway Sandboxes bill VM CPU+RAM the whole time the VM is up, including the idle-timeout window, then destroy. Short idleTimeoutMinutes is the cost control, not hibernation.
Floors matter as much as rates. E2B Pro is $150/mo before a second of compute. Runloop Pro is $250/mo. Sprites gates concurrency behind $20–$2,000 plans. Cloudflare needs Workers Paid ($5). Vercel Sandbox on Pro is the $20 Vercel plan. Daytona and Blaxel have no subscription floor. Modal gives ~$30/mo credits.

Two further data points, different methodologies:

  • sandbox-comparison.pages.dev (17 Jan 2026) — E2B cold start 0.515 s (best of five), Daytona 0.753 s, Sprites ~1 s wake, Modal 1.512 s, Blaxel 2.9 s create / 25 ms advertised resume. Snapshot story in that run is stale: E2B has since shipped pause/resume with memory.

A fast median that fails is slower than 800 ms that always returns.
P99 is the agent metric. A 50-step loop hitting a 31 s stall ~40% of the time will feel broken even if the median is faster than E2B. Prefer providers that publish success rate and tail latency, or measure them yourself from the region you will actually call.

Persistence, checkpoints, forks

The ephemeral-vs-persistent argument is over. Everyone now has some way to keep a filesystem. The mechanisms are not equivalent.

MechanismWhat survivesWhoResume feel
Pause / resume in placeFS + RAM + processesE2B (beta_pause), Daytona VM pauseE2B pause ~4 s/GiB RAM, resume ~1 s (vendor). LogRocket resume 662 ms.
Hibernate / standbyFull state, $0 computeSprites (warm→cold), Blaxel (~15 s idle → standby)Sprites warm 100–500 ms, cold 1–2 s (vendor). Blaxel claims <25 ms; measured wake 1.9 s.
Filesystem snapshotDisk, not RAMModal, Vercel (auto on stop), Railway checkpoints, Daytona snapshotsBoot a new sandbox from the image. Vercel measured resume 3.3 s.
Fork / clone liveDisk clone, new VMDaytona, Railway, CodeSandbox live clone, E2B templatesThe parallel-eval primitive: one prepared baseline, N attempts.
Live volumeReal disk, no snapshot stepNorthflank attached volumes, Nirvana block storageNo restore tax; processes still restart.
Object mount (R2/S3)Files you put on the bucketCloudflare R2 FUSE, E2B rclone mountsNot a POSIX disk. Fine for artifacts, bad for node_modules.

Sprites checkpoints are the distinctive product: vendor ~300 ms, git-like, last N kept under /.sprite/checkpoints, and the guest can checkpoint itself before a risky install. Railway checkpoints are named disk snapshots stored server-side; fork clones filesystem but not processes. Vercel persistence is default — you opt out, not in.

Provider dossiers

E2B — the category default

Firecracker microVMs, Python-first SDK that every agent framework already has a connector for, 1B+ sandboxes started, claimed 94% of Fortune 100. Hobby: $100 one-time credit, 20 concurrent, 1 h max session. Pro: $150/mo, 24 h sessions, 100 concurrent (to 1,100). Compute $0.000014/vCPU-s and $0.0000045/GiB-s. Pause now keeps memory; paused boxes persist until you kill them. BYOC on AWS/GCP is enterprise (figures of $50/sandbox/month on top of cloud have circulated; confirm with sales). Open-source control plane is Apache 2.0.

Use when you need a known-quantity code interpreter and Firecracker. Skip when you need GPUs, hate the $150 floor, or want idle-free perpetual VMs — that is Sprites/Blaxel.

Daytona — speed pitch, Computer Use, messy OSS story

Pivoted from cloud-dev-env to agent infra in 2025. $24M Series A, ~$1M run rate in under three months (Ry Walker, June 2026). Advertises ~90 ms creates, unlimited session length, snapshots, fork, VNC/Computer Use across Linux/Windows/macOS/Android, GPU SKUs, SDKs in Python/TS/Go/Ruby/Java. List compute matches E2B exactly ($0.0504 / $0.0162). $200 free compute, no subscription floor, Windows guests extra. Default isolation is Docker; Kata/Sysbox are opt-in — read the security page before you put stranger code in the default runtime.

The public GitHub repo stopped getting core updates in June 2026 (last OSS v0.190.0, AGPL). ~72K stars measure what it was. Hosted product is what you buy. CreateOS’s 37% launch success rate is the number to re-measure before you bet a latency SLO on Daytona.

Vercel Sandbox — Firecracker for the Next.js agent

GA January 2026. Firecracker microVM, TypeScript SDK @vercel/sandbox, Python secondary. Persistence is default; snapshots on stop. Active CPU $0.128/vCPU-hr, provisioned memory $0.0212/GB-hr, creations $0.60/1M, transfer $0.15/GB. Hobby: 5 h active CPU/mo, 10 concurrent, 45 min max. Pro: 5 h max runtime, 2,000 concurrent. Region: iad1. No GPU, no BYOC.

Vercel’s own comparison vs E2B is honest about the shape: a 10 min wall / 2 min CPU eval is ~$0.02 vs E2B ~$0.03; at 1,000 sandboxes/day of 30 s wall / 10 s CPU, ~$63/mo including the $20 Pro plan vs E2B ~$191 including the $150 floor. The catch is measured resume (3.3 s) and a 31 s P99 in the ComputeSDK run. Great if you already deploy on Vercel and the agent is bursty. Poor if you need multi-region, GPU, or tight tail latency.

Cloudflare Sandbox SDK — containers at the edge, isolates if you can

Two products that get flattened in roundups. The Sandbox SDK (@cloudflare/sandbox) is a Linux container on Cloudflare Containers: exec, files, background processes, exposed services, R2/S3/GCS mounts. The Dynamic Worker Loader is a V8 isolate that Cloudflare calls “100× faster than containers” — Code Mode, not a general Linux box. Container start is seconds in independent runs (CreateOS 4.84 s median). Isolates start in milliseconds and cannot apt-get.

Billing is Containers: ~$0.072/vCPU-hr active, ~$0.009/GiB-hr, 10 ms increments, plus Workers requests, Durable Objects, and the $5/mo Paid plan. No GPU in the sandbox (Workers AI is next door). Persistence of the container dies on sleep unless you mounted a bucket; R2 backups have a short restore TTL. Pick this because you already live on Workers, not because it wins a cold-start table.

Fly.io Sprites — a small computer that sleeps

Firecracker microVM, persistent ext4 (NVMe cache + object store), hardware isolation, network policies the guest cannot edit even as root. Create 1–2 s; warm wake 100–500 ms; cold 1–2 s; checkpoints ~300 ms (vendor). CPU $0.07/CPU-hour of used time (6.25% minimum per second awake), RAM $0.04375/GB-hour (250 MB minimum), hot storage $0.000683/GB-hr, cold/object $0.000027/GB-hr. Running is billed; warm and cold are not. A 4-hour Claude Code session at 30% of 2 CPUs / 1.5 GB is ~$0.44 in their worked example.

Concurrency is gated by plans: Adventurer $20/mo (20 active), up through Mythic $2,000 (2,000). SDKs in JS and Go (@fly/sprites), REST, CLI. Prebaked Claude Code image, /.sprite/llm.txt so the agent understands the box. No GPU in Sprites. No BYOC. This is the product to study if you think “sandbox” should mean “stateful computer,” not “function with a filesystem.”

Modal — Python, GPUs, scale, gVisor

$355M raise at $4.65B, ~$300M annualized (Ry Walker). Sandboxes are gVisor containers with optional GPU, volumes, filesystem and memory snapshots, 5 min default lifetime, 24 h max, then snapshot/restore. Python-native; JS/Go SDKs still beta. Sandbox CPU is priced at a premium to Modal functions (~3×). 50,000+ concurrent is the scale claim. No BYOC. Measured create ~2.4 s. The right tool when the code in the box needs a GPU or you already run Modal functions; an awkward code-interpreter if you wanted Firecracker and a one-liner create().

Railway Sandboxes — the VM next to the app

Railway (Priority Boarding / VM primitive) exposes sandboxes as programmable Debian VMs scoped to an environment. Isolation is the VM, not a shared-kernel container. CLI + TypeScript SDK (Sandbox.create / exec / checkpoint / fork / destroy). Default network is ISOLATED (egress only); PRIVATE joins the project’s private DNS so the agent can talk to the same Postgres and Redis it will deploy against — that is the distinctive move, and also the way you accidentally hand untrusted code a production database. Don’t.

Billed while the VM exists: $50/vCPU-month and $50/GB-month ($0.00000001929012 per MB·s and per vCPU·s) plus $0.05/GB egress. Idle still meters until the timeout fires (Hobby/Pro default 30 min, max 120; Free max 5). Caps: Hobby 50 sandboxes/environment, Pro 100. Checkpoints are named disk snapshots (count against the cap). Fork copies filesystem, not RAM. As of 26 Jun 2026 the default image ships Claude Code, Codex, Cursor, Droid, OpenCode, and Pi. No public GPU SKU, no Firecracker-on-the-tin, no idle-free hibernate. If the agent’s job is “work on this project,” this is the least fictional environment.

Northflank — price and BYOC

Lowest published PaaS CPU in the set ($0.01667/vCPU-hr, $0.00833/GB-hr), Kata microVM or gVisor per workload, GPU SKUs cheaper than Modal, self-serve BYOC onto AWS/GCP/Azure/Oracle/CoreWeave/Civo/bare metal with a management fee ($0.01389/vCPU-hr + $0.00139/GB-hr). CreateOS TTI 0.38 s median, 100% success. SDK/REST rather than a famous one-liner. If cost at hundreds of concurrent sandboxes is the constraint, start here and only leave for ecosystem reasons.

Blaxel and Runloop — resume-first specialists

Blaxel built the product around perpetual hibernation: ~15 s of idle → standby snapshot including processes, claimed <25 ms resume, memory-tier SKUs (XS 2 GB $0.0828/hr through XL 32 GB $1.32/hr), SOC 2 + ISO 27001 + HIPAA BAA. LogRocket measured 2.8 s create and 1.9 s wake — the 25 ms number is not what a cold client sees. Zero idle compute is still the point.

Runloop is dual-layer (microVM + container), snapshot/branch, claimed ~25 ms resume, $0.108/CPU-hr + $0.0252/GB-hr, $250/mo Pro, enterprise VPC. Aimed at coding agents that want a durable VM with a sales motion. No public GPU.

Security notes that survive the brochure

  • MicroVM ≠ safe network. AWS AgentCore’s 2026 write-up is the canonical reminder: DNS tunnelling and credential harvest work if the policy allows them. Sprites’ allowlist-not-denylist, enforced outside the guest, is the pattern to copy even if you do not buy Sprites.
  • Default Daytona is a container. If the threat model is “model-generated code from a stranger,” turn on Kata/Sysbox or pick a Firecracker host. Do not assume the homepage isolation paragraph is the default runtime.
  • Private networking is a feature and a foot-gun. Railway’s PRIVATE mode is excellent for “agent vs staging Postgres” and catastrophic for “agent vs prod.” Isolate by default; join a dev environment explicitly.
  • Computer Use expands the blast radius. A VNC desktop with a browser is why Daytona (and Google’s browser sandbox) exist, and also why network + clipboard + file exfil need their own policy, not just “it’s a VM.”
  • Self-hosting shifts the CVE, not the work. OpenSandbox, Microsandbox, Daytona’s frozen AGPL tree, E2B’s Apache plane — you still patch Firecracker, gVisor, and the control plane. Budget for that or don’t pretend you did.
