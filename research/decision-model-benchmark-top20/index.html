How it was scored

  • 30 mock skills, one fixed inventory. Each model scores every skill 0 to 2 for the prompt; a skill is picked when its score is at least 0.75 (threshold 0.375), at most 12 per run. This is the production score-only picker of pi-context-decisions.
  • The “should pick” sets were written before any model was called and do not overlap, so a model that returns the same skills for every prompt cannot score well. “Acceptable” skills are plausible helpers: allowed, never counted as off-topic, never required.
  • Precision = correct picks ÷ all picks. Recall = correct picks ÷ should-pick. F1 is their harmonic mean. Wrong pick = a pick that is neither should-pick nor acceptable. Accuracy = (correct − wrong) ÷ should-pick. Exact set = picked exactly the should-pick skills and nothing else.
  • Latency is the whole picker call (two parallel requests of 16 skills each). Cost is the provider-reported cost per decision; free variants report zero, which is not a pricing guarantee.
  • Roster: top 20 concrete decision variants by prompt + completion tokens, 2026-11-17 to 2026-11-23 UTC, from OpenRouter's public rankings. Paid and free variants are separate. Popularity is not a quality measure.
  • Limits: one labeler, three prompts and 30 skills. Standard deviations mix prompt difficulty with repeat noise. Read the ranking as a signal, not a significance test.
