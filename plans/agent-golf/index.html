01 / IMPLEMENTATION PLAN

A small website. One submit command.

Host Agent Golf at https://agent-golf.arnav.tech. Users register a username, save a one-time token, install a small collector, and submit existing coding-agent sessions. The server parses the uploaded traces and adds the resulting metrics to the leaderboard.

Trusted mode: we trust users and their harnesses to provide truthful traces and measurements. Zero-trust prevention is deferred; abuse scenarios are listed at the end.

This is the current build plan. It supersedes the earlier capture-first workflow in the Agent Golf research report. No task initialization, capture wrapper, daemon, background service or local verifier is required for ordinary submission.

Website

Register a username, show the token once, explain installation, display a leaderboard and submission details.

Collector

A downloadable executable. Discover local agent sessions, let the user select one, upload its trace bundle, then exit.

Target support: Claude Code, Codex, Copilot CLI, Pi and Antigravity. Support discovery and parsing through versioned adapters. Antigravity support is a required implementation workstream with an unresolved export-format gate, not something to claim complete without a real fixture.

This document publishes the plan only. Creating the backend, provisioning the domain and releasing executable installers are subsequent implementation work.

The entire web interface

No email, password, OAuth, profile editor, password reset or account-recovery flow. Losing the saved token means registering a new username. Existing usernames and their submissions remain; a lost token does not free the username.

Registration contract

  1. Accept usernames matching [a-z0-9_]{3,32}; normalize to lowercase, enforce uniqueness in the database, and reserve system names.
  2. Generate a cryptographically random UUIDv4 bearer token on the backend. The UUID user ID is a separate value and is never accepted as a credential.
  3. Store SHA-256(token) in the user row and return the plaintext token only in the creation response. This preserves the requested database-backed token login without retaining a recoverable plaintext credential.
  4. Return HTTP 201 with {user_id, username, token}. A duplicate username returns 409; invalid input returns 422. Disable response caching and do not log registration response bodies.

A lost registration response is equivalent to losing the token: there is no recovery endpoint. The client installer saves the token locally, so normal submissions do not ask for it again. Anyone possessing the token can submit as that user; this is the intended minimal authentication model.

Use bearer authentication for submissions and private downloads. Public leaderboard reads do not require a token. Basic registration/upload rate limits protect service availability; they do not attempt to solve competition cheating.

03 / IMPLEMENTATION PLAN

Install once, save the token locally

The website displays this proposed command:

curl -fsSL https://agent-golf.arnav.tech/install.sh | sh -s -- --token "SAVED_TOKEN"

--token is an argument to the downloaded script, not a curl flag. Also support a download-then-run form:

curl -fsSL https://agent-golf.arnav.tech/install.sh -o /tmp/agent-golf-install.sh
sh /tmp/agent-golf-install.sh --token "SAVED_TOKEN"

These are future product commands, not currently deployed endpoints. The token does not belong in the installer URL or query string. Offer a prompt-based alternative for people who prefer not to place it in shell history: download the script, then run it without --token.

Installer behavior

  1. Detect OS and architecture. Provide Go binaries for macOS arm64/amd64 and Linux arm64/amd64, plus a Windows binary and PowerShell installer. WSL uses the Linux path.
  2. Read the supplied token or prompt locally. Validate it using GET /api/v1/me before replacing existing configuration. Never echo the token.
  3. Fetch an HTTPS release manifest and the matching versioned binary; check its published SHA-256. A checksum detects corrupt downloads; it is not independent protection if the distribution server is compromised.
  4. Install without sudo into ~/.local/bin/agent-golf on Unix. Use a per-user executable directory on Windows. Show the PATH command if needed; do not silently rewrite shell startup files.
  5. Write server_url and token into a user configuration file, atomically. Set Unix directory/file permissions to 0700/0600; use user-restricted permissions on Windows.
  6. Print the username, installed version and “Run agent-golf submit from any folder.” Exit. Install no service, scheduled job, shell hook or agent instrumentation.

Use the OS user-config directory: $XDG_CONFIG_HOME/agent-golf/config.json or ~/.config/agent-golf/config.json on Linux; ~/Library/Application Support/agent-golf/config.json on macOS; %AppData%\agent-golf\config.json on Windows. Resolve these through the standard library. Re-running the installer upgrades the executable and preserves configuration unless a new token is explicitly supplied.

Release manifest fields: version, minimum API protocol version, OS/architecture artifact URLs, SHA-256 and supported agent-adapter versions. Reject unsupported OS/architecture with a useful message. The collector can report that an upgrade is needed but does not self-update on every submission.

04 / IMPLEMENTATION PLAN

What agent-golf submit does

cd any-project-or-folder
agent-golf submit
  1. Load configuration and validate identity. If no token exists, show installation/setup instructions. If invalid, exit with 401 guidance before uploading anything.
  2. Discover local sessions. Search known agent data directories and configured overrides, not the entire disk. Use the current folder and Git root to prioritize matches; the command must also work outside a Git repository.
  3. Display the selector. Group by agent, newest first. Each row shows agent, session ID, last activity, project path and local title/first-prompt preview. Label related-project matches, unknown-project sessions and unsupported formats.
  4. Choose a session. Search, use arrows/Enter, or use a numbered menu when a rich terminal is unavailable. Current-project sessions appear first; “All local sessions” is always available. Never silently submit the newest session.
  5. Prepare a snapshot. Include the selected trace plus discoverable linked child/fork records needed for that session. Preview the number of files, bytes and scope; do not upload unrelated sessions or the whole agent home directory.
  6. Confirm upload. Show username, agent, selected session and included files; Enter submits and Escape cancels. State that traces may contain prompts and code, and that raw content remains private.
  7. Upload once. Send the token in the Authorization header and an idempotency key in a request header. Save a local receipt so retrying after a timeout can recover the same submission.
  8. Show the result. Poll for up to 30 seconds. Print parsed metrics and a submission URL when ready; if still processing, print the URL and exit. The server finishes independently.

Folder association

Canonicalize the current path and selected session’s recorded working directory. Prioritize exact directory, then same Git root/worktree, then other local sessions. Use path metadata, not just encoded directory names. Sessions from a moved project remain selectable. Do not merge unrelated worktrees or sessions automatically.

Useful optional flags

agent-golf submit --agent pi
agent-golf submit --all-projects
agent-golf submit --agent codex --session SESSION_ID --yes
agent-golf submit --agent antigravity --trace /path/to/export
agent-golf submit --dry-run
agent-golf status SUBMISSION_ID

Non-interactive execution requires an explicit session or trace and --yes; otherwise fail with instructions rather than guessing. --dry-run lists the bundle without sending it. Keep flags secondary to the basic interactive command.

Sessions still being written

Read a stable, bounded snapshot through the last complete record. Retry a small number of times if size/mtime changes; if the session continues changing, ask the user to finish it or explicitly upload a partial snapshot. Show partial coverage. Never lock or alter an agent’s live database. For SQLite sources, use read-only database APIs and a consistent snapshot rather than copying a database file without its WAL.

All-five support acceptance gate

For each agent: discover a real completed session, show the correct project/session metadata, select it, snapshot it safely, parse it server-side and show honest metric coverage. Test both installation-default and overridden locations. If Antigravity requires manual export for a specific version, disclose that limitation; the fully automatic five-agent requirement remains open until resolved.

06 / IMPLEMENTATION PLAN

Leaderboard entries from existing traces

Every successfully parsed upload creates an entry with username, agent/model, session date, tool calls, human prompt count, human prompt characters, code-line metrics, input/output/cache tokens and total tokens. Display unknown values as an em dash with a reason. A missing field never becomes zero.

Scope change from the earlier report: this product submits a selected saved session, not a required instrumented attempt. Include discoverable linked child/continuation records and all branches belonging to the submitted scope. Record missing dependencies as partial coverage. The server cannot reconstruct work deleted before submission.

Ranking policy

  • Show a public submission table immediately after parsing, sortable by any metric and filterable by agent/model.
  • For Token Golf, rank rows with a complete total by ascending total_tokens. Exact ties share a rank. Display prompts and tool calls alongside.
  • Rows missing the chosen ranking metric remain visible below ranked rows, labelled unranked for that metric. They can rank on other complete metrics.
  • For a real course competition, use a shared board/task version (a server default can avoid another CLI prompt). Compare winners only within that task and declared model/harness division.

Do not call the smallest arbitrary session the best solution across unrelated tasks. In this minimal release, rows are trusted session statistics; correctness is unverified. A later competition may accept a truthful completion/verifier report or add evaluation, but neither is required by agent-golf submit.

What post-session collection cannot recover

Saved traces may omit original human input before template expansion, provider usage, hidden/auxiliary calls or intermediate file writes. Report the observed amount and coverage. A client may optionally attach truthful supplemental measurements using the earlier report contract, but no extra reporting ceremony is required for the normal submission flow.

For code, show emitted_code_lines or gross_added_source_lines only when the trace supports them. A final workspace diff is a different measurement and requires a known baseline plus the actual final artifact. Do not read today’s working tree and attribute it to a historical selected session. No repository upload is required in v1.

Reuse the precise metric rules below, with unavailable post-hoc measurements left unknown. ATIF is an optional normalized export/interchange layer; do not make the client convert every native trace to ATIF before upload.

Metric definitions

Apply these definitions to the selected session bundle and its declared coverage. An all-work “attempt” is optional metadata, not a mandatory capture workflow.

MetricNormative rule proposed for v1
tool_calls_requestedCount each distinct model/harness-issued tool invocation once, including failed, denied and cancelled requests. Results and stream updates are not new calls. Expose executed, succeeded, failed, denied and cancelled breakdowns separately.
human_prompt_countCount each submitted human instruction or steering message once, including a repeated identical prompt. Exclude tool results, generated summaries, system instructions and subagent delegation messages. Track permission-only clicks separately. Built-in navigation commands are not prompts; commands that instruct model work are.
human_prompt_charsSum Unicode code points of submitted human text, after CRLF/CR → LF. Preserve spaces and trailing newlines; no trimming or Unicode normalization. Python len(text) after newline normalization; JavaScript [...text].length. Count typed template invocation text; record expanded content separately.
model_requestsCount actual dispatched inference requests, including paid failures, retries, compaction and nested model work. UI assistant messages, reasoning chunks and ATIF steps are not equivalent to requests. Unknown if only aggregate usage exists.
agent_cyclesOptional harness-specific human-prompt-to-yield cycles. Display descriptively; never compare unnormalized vendor “turns.” Use model_requests for the Model-call Golf board.
total_tokensSum input and output with cache counted exactly once and reasoning counted according to its inclusion relationship. Include every request in the attempt. See the accounting contract below.

Three parallel tool invocations count as three. One shell invocation containing ten commands counts as one tool call. A delegation invocation plus five child tool invocations counts as six. This is an interface metric, not a measure of computational work; compare tools primarily within a fixed harness/configuration.

Prompt length versus supplied context

Record task_prompt_chars, participant_context_chars, attachment bytes and expanded-template characters separately. Keep organizer-supplied task text separate from human instructions. Rules files, skills, pasted files and image attachments can add large context without increasing typed prompt length. Their model input tokens still count. Start Prompt Golf with text-only inputs and a fixed, declared rules/skills configuration; use a separate open-context division if students may customize it.

Keep LOC as a descriptive metric in v1, not a ranking objective. Otherwise minification, code formatting, generated files and code reuse can dominate the competition for reasons unrelated to agent efficiency.

Token normalization

Normalize to disjoint input buckets and one inclusive output bucket. Preserve raw provider fields and their inclusion semantics alongside the normalized value. Anthropic separates ordinary input, cache creation and cache reads in usage. Codex’s JSON interface reports input, cached input and output. Anthropic cache accounting; Codex events.

T = U + R + W + O

U = uncached input excluding cache creation · R = cache-read input · W = cache-write input · O = all output, including reasoning when reported.

Source contractNormalization
Input already includes cache reads/writesU = input − R − W; total is input + O. Unknown cache split does not invalidate a known inclusive input total.
Input excludes separately reported cache reads/writesU = input; total is input + R + W + O.
Reasoning is a subset of outputKeep it as an informational subfield. Do not add it again.
Reasoning is explicitly excluded from outputAdd it once to construct O. If the relationship is undocumented, report the complete total as unknown until the harness supplies the contract.
Cache duration sub-bucketsA 1-hour creation field may be a subset of total cache writes. Store the breakdown; do not blindly add every field.

Try the accounting

Illustrative numbers, not a provider benchmark. Change the input convention to see why identical field names can produce different totals.

Correct total12,000

Reducer rules that avoid accidental overcounting

  1. Choose one authoritative source per coverage scope. Prefer complete per-request usage; otherwise use a declared turn/session aggregate or harness report. Never add aggregate totals to the requests they already contain.
  2. Use finalized request records. Streaming chunks may repeat cumulative usage. Join by session, agent and request identity; sum finalized records once. Retries are distinct requests, even with the same prompt.
  3. Delta cumulative counters only within a documented epoch. Record process restarts, reset points and start baselines. A decreasing counter needs an explicit reset, not silent clamping. Histogram sample counts are not token totals.
  4. Include child and auxiliary work once. A parent may already include child usage. Require a scope declaration and request references when available. A nesting relationship alone does not tell you what a total includes.
  5. Never retokenize visible chat as actual usage. It misses hidden context, repeated input, tools, reasoning and compaction. Optional estimates belong in separate fields and do not qualify for Token Golf.
  6. Unknown is null. Publish coverage for total usage and each breakdown independently. A known total with an unknown cache split can rank; an unknown total cannot. Zero means measured zero.

For example, two requests with 10,000 input tokens each count 20,000 input tokens, even if they reuse the same context. Cached tokens still count in Token Golf. A separate cost view may discount cache hits using a versioned price table, but subscription fees and Copilot billing multipliers are not token counts.

Backend, endpoints and storage

Suggested implementation: Go collector for single-file cross-platform distribution; Python FastAPI/Pydantic backend and worker for parsers; PostgreSQL for users, submissions, jobs and summaries; S3-compatible storage for private trace bundles. Serve minimal HTML from the backend itself. No separate SPA is needed.

3 · WorkerDetect, parse, normalize, reduce and store versioned metrics.
4 · LeaderboardRead database summaries and show the result.

The server derives ownership from the bearer token, never a submitted username. Validate that every manifest file matches uploaded bytes. Preserve native records as evidence; parse metadata on the server rather than trusting a collector’s guess when the trace supplies it. Unknown version is allowed to reach format detection, not silently mapped to the newest parser.

Status lifecycle: queued → parsing → parsed; alternatives unsupported_format, invalid_bundle, failed. Parsing succeeds with partial metrics when possible. Publish a leaderboard row only after the evaluation transaction commits. Record parser/policy versions so reprocessing does not silently change historical scores.

Duplicates, retries and revisions

Canonicalize the content digest from sorted filenames and their hashes, excluding upload timestamps. Enforce unique (user, agent, session ID, snapshot digest). Repeating identical bytes returns the original entry, even with a new idempotency key. A changed snapshot creates a revision; retain earlier versions but show the latest successfully parsed revision by default. Reusing the same idempotency key with different bytes returns 409. If an upload times out, retry with the same key.

Start with a Postgres jobs table and leased workers; no Redis is required. Retry transient failures with a cap. Parsing failures should provide specific diagnostics, not infinite retries. Store archives privately, reject traversal paths and oversized decompression, bound parsing memory/time, and render user text escaped. No uploaded code executes on the backend.

10 / IMPLEMENTATION PLAN

Host the product at agent-golf.arnav.tech

Deploy an API/web container, parser worker, Postgres and private object bucket. A platform such as Railway or a small VPS can run this topology; choose the provider during implementation. No infrastructure is being provisioned by this plan publication.

  1. Create the application services and database, apply migrations and configure storage credentials through deployment secrets.
  2. Attach agent-golf.arnav.tech to the web service. Use the hosting provider’s actual supplied DNS target; do not guess a CNAME value. Enable HTTPS before issuing tokens.
  3. Serve the website, API, installers and release manifest under the same origin. Use versioned immutable paths for executable assets.
  4. Configure database backups, private-object retention, queue/error monitoring and request-body/header redaction. Do not log bearer tokens or full trace uploads.
  5. Run an end-to-end registration/install/submit check using test users before announcing the service.

Initial configurable limits: 100 MB compressed per upload, 500 MB expanded, 1 million records and a bounded worker timeout. Handle honest large sessions with a clear error and explicit operator-configured limit increases. Stream uploads rather than buffering them in RAM. Persist raw bundles long enough to reparse schema changes; start with 90-day private raw retention and retain public aggregate entries separately.

Public data: username, agent/model, timestamps, metrics and coverage. Keep session prompt previews and local project paths on the client; private traces may still contain them. Token-based authentication is for attribution and private access, not proof of honest usage.

Essential tests

  • Case-normalized username uniqueness; random token issuance; valid/invalid bearer auth; no token in logs or public JSON.
  • Install on supported OS/architectures; invalid token leaves prior config intact; repeat install preserves config; no background process remains.
  • Discovery inside/outside repositories, moved projects, custom roots, missing directories and non-interactive selection.

  • Accounting fixtures: inclusive cache, repeated usage updates, nested usage overlap, Unicode prompts, tool failures and partial LOC.
  • Public entry appears after parse; raw uploads stay private; unknown values never win a metric leaderboard.

Definition of done: a user can register, save their token, install the collector, run agent-golf submit from any folder, select a supported existing session and receive a backend-parsed leaderboard entry without starting a collector before the coding session.

Zero trust: abuse notes only

Per scope: zero-trust implementation is not required now. Do not add managed runners, cryptographic attestation, provider-side reconciliation or anti-cheating infrastructure to the trusted-mode milestones. The list below is a future threat-model backlog.
Possible abuseWhat becomes falseQuestion for later
Fabricated JSONL or edited metric reportPrompts, calls or token counts never occurred as reported.What would establish authentic execution?
Deleted expensive requests, failed turns or branchesA locally plausible trace understates the attempt.How could completeness be established?
Omitted subagents, compaction or off-session model callsWork is outsourced beyond the declared boundary.Which external work should count, and how could it be observed?
Code or solution prepared before captureThe trace records only the final cheap step.What constitutes the real start of an attempt?
Different final artifact from the one in the traceReported code and submitted solution do not match.How could artifact provenance be established?
Forged verifier results or modified testsA failing solution qualifies as correct.Who must execute and control verification?
Hidden rules, skills, attachments or external human helpA tiny visible prompt conceals the actual instructions.What assistance is allowed and measurable?
Mislabelled model/version/provider or token semanticsThe run enters a more favorable division or undercounts usage.How could model identity and usage units be established?
Reused session, copied submission or manipulated attempt IDsOwnership, uniqueness or attempt limits are misrepresented.What identity and originality guarantees are necessary?
Code minification or one giant shell commandLOC/tool metrics are optimized without reducing actual work.Is this allowed strategy or a flaw in the objective?

Trusted mode deliberately accepts the honesty assumption behind these scenarios. Structural checks can catch mistakes, but a valid schema, matching checksum or internally consistent trace is not evidence against deliberate fabrication.

Research basis and open questions

This plan builds on the original Agent Golf research and metric specification. Product decisions above are proposals; vendor storage layouts must be pinned and tested before release.

  • Copilot CLI best practices: session-state storage and metadata.
  • Pi session format: location, tree and usage fields.
  • Claude Code monitoring: transcript location and version-sensitive schemas.
  • Codex advanced configuration: CODEX_HOME and local state; verify native storage per supported release.
  • Harbor ATIF: optional interchange foundation.
  • Antigravity export issue: a user-reported export gap, not a definitive specification.

Open before full implementation: exact Antigravity storage/export per surface; auxiliary-usage coverage in each native format; reconstructable LOC definitions; exact supported agent-version matrix. The product workflow is settled; these are adapter capability questions.
