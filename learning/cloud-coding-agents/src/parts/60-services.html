Two ways in — pick per side project.

Cloud agent: SSH or desktop app in, credentials carried, files persist, sleep when done.

Sandboxes: an isolated VM per task, on the private network with your real services.

Checkpoint once, then fork per task. The repo-review demo fans out one sandbox per agent.

Both meter per second. Sleep or destroy, the meter stops.

Walk the four clicks. One: a cloud agent is a persistent dev machine — railway code with Claude, Codex or OpenCode, six harnesses preinstalled in the image, credentials carried from your laptop, files on disk across disconnects, sleep to stop compute while keeping files. Two: sandboxes are the opposite shape — short-lived isolated Linux VMs, one per task, optionally on the project's private network so the agent tests against your real Postgres, Redis and internal APIs instead of mocks. Three: amortise setup — clone once, install once, sign agents in once, checkpoint the disk as repo-ready, then create or fork one sandbox per task from it. Railway's own repo-review demo does exactly this: one sandbox per agent, in parallel. Four: both bill per second on CPU and memory actually used. Sleep the agent or destroy the sandbox and billing stops. Say the honest trade out loud: checkpoints preserve disk, not live RAM. Sleep keeps files but stops processes. For a side project that is exactly the right trade.

Step 1 lights up the RAM-preserving row: E2B pauses the live VM with memory included and resumes in about a second, paused free; Daytona VM sandboxes preserve memory on pause and bill disk-only while parked; Fly suspends the whole VM including RAM and wakes in hundreds of milliseconds. Step 2 covers snapshot-restart: Vercel stop auto-snapshots the filesystem with tiered timeouts; Cloudflare backs directories up to R2 with a 3-day default TTL and restores them as an overlay; Modal snapshots become restorable clones. what parking costs

Running bills you; parked costs pennies.

🔥

While running

  • CPU + RAM actually used, per second
  • + creations, egress
  • every service meters this

❄️

While parked

  • E2B paused: free
  • Daytona / Fly: disk only
  • Vercel / CF / Modal: snapshot storage
  • Railway destroyed: $0
Two clicks. While running, everyone meters CPU plus RAM per second, plus creations and egress — that is the same everywhere. While parked, the bill collapses: E2B paused sandboxes are free, Daytona and Fly charge disk only, Vercel, Cloudflare and Modal charge snapshot or backup storage, and a destroyed Railway sandbox bills nothing at all. That collapse is the whole business case: the waiting money from section two goes nearly to zero.
