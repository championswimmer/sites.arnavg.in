Choose based on how long you need the workspace.

Cloud agent: return to the same files across sessions.

Sandbox: give each task its own environment.

Checkpoint once. Avoid repeating setup for every task.

Stop the compute when the task ends. Check what storage remains.

A cloud agent is a dev machine you return to. A sandbox is a workspace for one task. Both can use prepared disk state. Neither disk checkpoints nor sleep preserve running processes. Use scoped credentials and test services on the private network. Save the result before destroying a sandbox. Compute and retained storage are separate billing questions.

read the bill in two parts

Stopping compute is not always a $0 bill

While running

  • CPU: used or allocated, by provider
  • RAM: often provisioned capacity
  • Disk, network and creation fees may apply
  • Model tokens are a separate cost

After stopping

  • Pause can end compute charges
  • Snapshots, disks and backups may still bill
  • Retention limits affect how long state survives
  • Delete state only after saving the result
Providers meter resources differently. Do not assume every service bills only actual CPU and RAM use. Pausing reduces compute cost, but retained state can still have a bill and an expiry date. Check both before leaving hundreds of sessions idle.
