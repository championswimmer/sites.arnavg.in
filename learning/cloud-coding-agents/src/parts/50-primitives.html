Six APIs, two shapes.

RAM-preserving: E2B and Daytona pause the live VM — memory included.

Snapshot-restart: the rest restore the filesystem into a fresh session.

Railway: checkpoint/fork per environment — app-adjacent workers, not thousands of agent VMs.

Let the audience click cards; details appear below. Step 1 lights up the two RAM-preserving picks: E2B's pause saves filesystem plus memory by default with about-a-second resume, paused free; Daytona VM sandboxes preserve memory on pause, filesystem on stop, parked VMs bill disk only. Step 2 covers snapshot-restart: Fly suspends via Firecracker snapshots in hundreds of milliseconds but discourages huge or mass suspends; Vercel stop auto-snapshots the filesystem with tiered timeouts; Cloudflare backs up to R2 with a 3-day default TTL; Modal snapshots become restorable clones with a 7-day TTL. Step 3: Railway checkpoints and forks whole sandboxes per environment — fine for ephemeral workers, not the thousands-of-pausable-VMs shape.

what parking costs

Running burns. Parked sips.

🔥

  • CPU + RAM, per second
  • + creations, egress
  • every platform meters this

❄️

While parked

  • E2B paused: free
  • Daytona / Fly: disk only
  • Vercel / CF / Modal: snapshot storage
Two clicks. While running, everyone meters CPU plus RAM per second, plus creations and egress — that is the same everywhere. While parked, the bill collapses: E2B paused sandboxes are free, Daytona and Fly charge disk only, Vercel, Cloudflare and Modal charge snapshot or backup storage. That collapse is the whole business case: the waiting money from section two goes nearly to zero.
