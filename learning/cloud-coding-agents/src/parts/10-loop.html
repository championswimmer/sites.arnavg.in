repair loops back to act until checks pass

Each step needs tools, state and the right permissions.

Plan: read the ticket and inspect the repo.

Act: edit files, run commands and call tools.

Observe: read logs, exit codes and CI results.

Repair: reproduce the failure, fix it and run again.

Handoff: open a PR and link the ticket. Deploy with approval.

Give each step only the access it needs.

Walk through the five steps. The harness runs locally; models and remote tools may live elsewhere. Separate local file writes from permission to push to GitHub. Cloning only needs read access. Debug against staging or scrubbed test data. A passing test does not grant permission to deploy.

Review the diff alongside the test results.

Here the agent uses scripts to search, try fixes and run tests. These commands are an example session. A script can batch work that would otherwise take many tool calls. Files and background services can persist between calls. Shell variables only persist if the harness reuses that shell. Tests provide evidence, not a guarantee. Review the patch too.
