# Build guide: "Building your coding harness" deck

A **speaker-led** reveal.js talk for an AI conference audience on a big screen. Attendees use AI coding
tools but have never changed a harness or written an extension. The speaker drives the deck with a clicker
or arrow keys. It is not a self-serve reading page.

## Folder layout

```
building-your-coding-harness/
  index.html          ← GENERATED by `node build.mjs` (do not hand-edit)
  build.mjs           ← concatenates src/head.html + src/parts/*.html (sorted) + src/tail.html
  src/head.html       ← theme tokens, shared components, Deck step engine (read it!)
  src/tail.html       ← reveal init (1600×900 canvas, notes + highlight plugins)
  src/parts/NN-*.html ← one file per section, containing only <section> elements
  research/*.md       ← source-verified research; slides must match it
```

Parts: `00-intro` (done), `10-harness`, `20-lifecycle`, `30-speedometer`, `40-checklist`, `50-context-prune`, `90-outro`.
The three extension walkthroughs are ordered by how much they change the harness: speedometer observes, checklist adds a tool, context-prune rewrites the loop.

Preview only your part: `node build.mjs --only 30`, then open `.preview/30.html`. Never write index.html yourself.
Node is available via nvm. If `node` fails, run `source ~/.nvm/nvm.sh` first.

## Hard rules

1. **Readable from the back of the room.** Canvas is 1600×900. Body text 22pt (default). **Nothing below 15pt**,
   including diagram labels, SVG text (SVG `font-size` ≥ 20 user units at 1:1 scale), code, and chips.
   Code blocks 16–18pt, ≤ 14 lines. Aim for ≤ 35 visible words per slide, excluding code and diagram labels.
   Put detail in speaker notes, not on the slide.
2. **Diagrams and interactions carry the talk.** Most slides in a walkthrough should be `stepper` slides whose
   diagram changes as the speaker clicks. The interactions, diagrams and visualisations stay on the slides.
3. **Speaker notes on every slide** (`<aside class="notes">`): what to say at each step, 2–6 sentences, plus demo tips.
   The notes may be detailed; the slide may not.
4. **Accuracy:** every claim, event name, code excerpt and number must match `research/*.md`. Label illustrative
   numbers as illustrative in the notes. Code excerpts must be faithful, lightly trimmed, and annotated with a `code-label` file path.
5. Every `<section>` needs a **unique id prefixed by your section**, e.g. `cp-`, `lc-`, `hn-`, `sp-`, `ck-`.
   Scope all CSS with that id (`#cp-flow .block {…}`) in a `<style>` inside the section. Wrap JS in an IIFE.
6. No new external libraries. Reveal 5.1, the highlight plugin (`<pre><code class="language-ts" data-trim data-noescape>`),
   and Google Fonts are already loaded. Draw diagrams with inline SVG or HTML/CSS (grid/flex + transitions).
7. Every slide must fit 1600×900 with **no overflow**. The content box is the section minus 36px/64px padding.
   Keep the bottom ~70px free when using `.captions`.
8. Text belongs in `<p>`, `<li>`, `<h*>` (they inherit the theme), or in explicitly sized spans/SVG text.

## Theme (from src/head.html)

Semantic colours. Use them consistently:
`--amber` pi core/harness · `--teal` events & hooks · `--violet` extension code · `--blue` model/provider ·
`--coral` tokens, cost, blocked, danger · `--green` saved, success · `--panel`, `--panel-2`, `--line`, `--muted`.
Fonts: `--head` Space Grotesk, `--body` Inter, `--mono` JetBrains Mono.

Components: `.kicker` (small section label above h2), `.card` (+ `.amber/.teal/.violet/.blue/.coral/.green` border),
`.hook` (event chip; `.hot` = glowing active, `.mut` = shows ✎ for "can modify"), `.term` (pi terminal mock with
`.bar` (three `<i>` + `<b>title</b>`), `.body`, `.status`), `.captions` (absolute bottom caption area holding several
`<p data-only="N">`), `.dots` (auto step dots), `button.btn` (`.active`), `.lead`, `.huge`, `.small`, `.muted`, `.t-<colour>`.
`section.divider` = centred section title slide (use `.num` for "02" etc).

## Step engine: tie diagram state to the clicker

```html
<section id="cp-flow" class="stepper" data-steps="6">
  <div class="block" data-at="2">shown from step 2 onwards</div>
  <div data-only="3 4">only during steps 3 and 4</div>
  <span class="hook" data-hot="1">context</span>   <!-- glows only at step 1 -->
  <div class="captions">
    <p data-only="0">Starting state caption</p>
    <p data-only="1">Caption for step 1</p>
  </div>
  <div class="dots"></div>
</section>
```

- The engine appends N invisible fragments. Each clicker press moves one step. Step 0 is the state on entering the slide.
- The section gets `data-step="k"` and classes `s1…sk` for reached steps, so you can write CSS like `#cp-flow.s3 .ctx .raw { height: 20px }`.
  Prefer CSS transitions driven by these classes. They reverse correctly when the speaker goes back.
- For computed or animated state use JS:
  `Deck.onStep('cp-flow', (step, sec) => { … })` (called on every change, including entering with a restored step),
  `Deck.onEnter(id, sec => …)`, `Deck.onLeave(id, sec => …)`. Write step handlers idempotently: derive the full view from `step` and never rely on the previous step.
  Timers and animations started in onEnter must stop in onLeave.
- Clickable extras (buttons, clicking an event to inspect it) are welcome **in addition to** the stepper.
  Don't make essential content reachable only by mouse. Call `e.stopPropagation()` in click handlers.

## Visual QA (required before you finish)

Use the `agent-browser` CLI (run `agent-browser skills get core` if unsure). Use your own isolated session via the env var
`AGENT_BROWSER_SESSION=<your-section-prefix>`, never the default one.

```sh
export AGENT_BROWSER_SESSION=cp
agent-browser set viewport 1600 900
agent-browser open "file://$PWD/.preview/30.html#/cp-flow"
agent-browser wait 2000
agent-browser press ArrowRight   # advance one step
agent-browser screenshot <scratch>/cp-flow-s1.png
agent-browser eval "(() => { const s = Reveal.getCurrentSlide(); return [s.scrollHeight, s.clientHeight, s.scrollWidth, s.clientWidth]; })()"
```

Screenshot **every slide at every step** (or at least its first, middle and last step), look at each image with the Read tool,
and fix overlaps, overflow, clipped text, tiny text and low contrast. Check for console errors. Delete temporary screenshots.
