From zero to a live extension in about a minute

We've seen three extensions: one that rewrites context, one that only watches, and one that gives the model new tools and keeps its own state. Now the question is what you would build. Here's how short that path is.

zero → live

No build. No fork. No restart.

1Write a .ts file

~/.pi/agent/extensions/guard.ts

export default (pi) => {

pi.on("tool_call", (e) => {

if (isToolCallEventType(

"bash", e) &&

e.input.command

.includes("rm -rf"))

return { block: true,

reason: "nope" };

});

};

Step 1: one TypeScript file in ~/.pi/agent/extensions. Pi loads it through jiti, so there's no compile step, and pi's own packages resolve without an npm install. The slide is trimmed for size; the real file imports isToolCallEventType from @earendil-works/pi-coding-agent. Step 2: /reload tears the runtime down and brings it back in the same session: session_shutdown with reason reload, then session_start. There's no file watcher, so you trigger it yourself. Step 3: the model tries rm -rf and the tool_call hook blocks it. The model gets the reason back as the tool result and adapts. Also worth saying: if a tool_call handler throws, the call is blocked, so it fails safe. Step 4: share it with pi install npm: or git:. Every extension in this talk is published that way.

Each click moves to the next hook, and you can also click any chip directly. These are ideas, not published extensions. tool_call: permission rules that fit your team. Pi deliberately ships without permission popups; the README says to build your own confirmation flow with extensions. context: a scrubber for secrets in tool output. This is the same hook context-prune uses. before_agent_start: dynamic instructions, the checklist pattern generalised. turn_end: observation only, the speedometer pattern. input: rewrite what the user typed before the agent runs. session_tree: rebuild state on branch jumps, as checklist does. The return shapes shown are the real ones from pi 0.85.1's type definitions.

All three extensions are published on npm. The install commands on the slide are the real package names. Leave this slide up during Q&A. Likely questions: Does it work with any model? Yes, pi is provider-agnostic, and hooks don't care which model is behind them. Is it safe? Extensions run with your full permissions, so only install ones you trust. How does this compare with Claude Code hooks? Those are shell commands at fixed points, while pi extensions are in-process TypeScript with typed events and return values.
