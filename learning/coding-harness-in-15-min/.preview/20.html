Pi's agent loop. Each stage fires named, typed events.

Input: the prompt arrives. The run hasn't started yet.

Context: a turn starts; you can rewrite what the model sees.

Provider: headers, the raw request payload, the response.

Stream: one message_update per delta.

Tool calls: inspect, patch or block before execution.

Tool results: patch the output before the model reads it.

[~1:30] Same loop as before, now with pi's real event names. Chips glow as they fire; click any chip for its payload and what it can return. Step 1, Input: input can transform or swallow the prompt; before_agent_start can inject a message or change this run's system prompt. Step 2, Context: context gets a deep copy of the messages before every LLM call. Rewrite it and the model sees something else; the session file is untouched. Step 3, Provider: before_provider_request can see or replace the exact payload. Step 4, Stream: a message_update per delta; message_end can replace the final message before it's saved. Step 5, Tool calls: tool_call runs after validation, before execute. This is where you block. Step 6, Tool results: tool_result patches the output before the model reads it. Steps 7–9: tools ran, so round again; turn 1 just answers, so turn_end, agent_end, agent_settled. Step 10: two kinds of hook. Observe: return nothing. Intervene: return a value. 14 of pi's 36 events can change the outcome that way; eight are on this loop. Handlers run one at a time, awaited, in extension load order, and results chain: the next handler sees the previous one's change (for tool_call, the first block wins). A slow handler slows the loop, even on message_update.

what is an extension?

One file. One function. It gets pi.

~/.pi/agent/extensions/hello.ts (illustrative)

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent"; export default function (pi: ExtensionAPI) { pi.on("turn_end", (event, ctx) => { ctx.ui.setStatus("turns", `turn ${event.turnIndex + 1}`); }); pi.registerTool({ name: "roll_dice", /* … */ }); pi.registerCommand("hello", { /* … */ }); }

[~0:35] So how do you hook in? An extension is a TypeScript file whose default export is a function. pi calls it once and hands you the API. Step 1: drop it in ~/.pi/agent/extensions or .pi/extensions, type /reload, it's live. No build, no fork. Steps 2–5: pi.on hooks any event from the loop we just saw; registerTool gives the model a new tool; registerCommand adds a slash command; ctx.ui paints the footer, widgets and dialogs.
