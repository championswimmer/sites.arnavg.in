[~1:45] Step 0: the model on its own is just a text function: text in, text out, no state, no hands. It can't read a file or run a command. Something has to run the tools and call it again. That's the harness. Task: "fix the failing login test". Files, test output and the size bar are illustrative; the loop shape is pi's real code path. Step 1: you type one line. Step 2: the harness builds the context: system prompt, AGENTS.md, tool definitions, history. The model knows only what's in this stack. Step 3: pi-ai turns it into a request for whichever provider you picked. The whole stack goes out on every call. Step 4: the reply streams back as text plus a tool call: bash, npm test. That's a request, not an action. Step 5: the harness validates the arguments and runs the tool. Multiple calls run in parallel by default. Step 6: the output is appended as a toolResult, and because there were tool calls, it loops. Steps 7–8: read the file, then edit it. Watch the stack: the test log and the whole file get re-sent on every later call. context-prune, the last extension, deals with exactly that. Steps 9–10: plain text, no tool calls, so the loop exits. One prompt, four model calls, three tool runs, all driven by the harness. Demo tip: "auto-play loop" runs it on a timer; click again to pause.
