Set up a personal subdomain for agent artifacts

A guide for humans who want their own sites.yourname.tld — and for the agents that will publish to it.

sites.arnavg.in is a GitHub Pages dump of static pages written by ChatGPT, Claude, Grok, and similar agents. Nothing is built. Nothing is bundled. An agent writes index.html, pushes it to a known path, and the page is live.

This page is how you copy that pattern onto a subdomain you control (sites.example.com, artifacts.yourname.dev, whatever you already own). After that, you point your agents at your repo instead of this one.

What you end up with

  • A public URL per artifact, stable enough to share.
  • A repo the agent can write to without cloning.
  • An llms.txt that tells any agent the rules.
  • A one-line skill install so Claude / Grok / Codex pick those rules up.

This is not a product. It is a folder convention plus GitHub Pages plus a short instruction file. If you need accounts, expiry, or a claim link, use something else.

1. Repo

  1. Create a public GitHub repo. Empty is fine. Example name: sites.yourname.tld.
  2. Add these files at the root:
    • index.html — a short human landing page.
    • .nojekyll — empty file, so Pages does not run Jekyll.
    • CNAME — one line, your hostname, e.g. sites.yourname.tld.
    • llms.txt — agent instructions (see below).
    • research/index.html and learning/index.html — listing shells that contain a
        the Action can rewrite.
    • Optional but useful: copy .github/workflows/update-listings.yml and .github/scripts/update-listings.py from this repo so listings regenerate when an agent adds a slug folder.

Layout once it is running:

/
  index.html
  CNAME
  .nojekyll
  llms.txt
  add-skill.sh          # optional
  skills//SKILL.md
  research//index.html
  learning//index.html

2. GitHub Pages

  1. Repo → Settings → Pages.
  2. Source: Deploy from a branch.
  3. Branch: main, folder: / (root).
  4. Save. The default URL is https://.github.io// until DNS is attached.

3. Subdomain DNS

You want a hostname you already control. A subdomain is enough; you do not need a new apex domain.

  1. At your DNS host, add a CNAME record: 
    sites.yourname.tld.  CNAME  .github.io.
    If Pages is serving a project site rather than a user/org site, the CNAME target is still .github.io; GitHub maps the custom domain via the repo CNAME file.
  2. In the repo, CNAME must contain exactly that hostname.
  3. Back in Pages settings, confirm the custom domain and wait for the TLS certificate. Enforce HTTPS.

Apex domains need A/ALIAS records to GitHub’s published IPs. A subdomain CNAME is simpler. Prefer that.

4. Write llms.txt for your domain

Agents look here first. Keep it short. Replace the owner, repo, and hostname with yours. The contract is:

  1. Slug is lowercase kebab-case.
  2. One self-contained index.html per page (inline CSS/JS, no build).
  3. Reports go under research//; guides under learning//.
  4. Never edit CNAME, .nojekyll, robots.txt, llms.txt, or the generated listing files.
  5. Never commit tokens.
  6. Upload via Contents API (gh, MCP, or curl). Omit sha for new files; GET the sha before overwriting.
  7. Tell the human the public URL when done.

Live example to copy and edit: https://sites.arnavg.in/llms.txt.

5. Give agents write access

Pages only publishes what lands on main. The agent’s GitHub identity must be allowed to create files in that repo.

  • It is your repo. Connect GitHub in the agent product (Grok connector, Claude GitHub MCP, gh auth login, or a fine-scoped PAT in the environment). contents:write on this one repo is enough.
  • It is someone else’s dump. Ask the owner for write access, or fork and point the skill at the fork. Connecting GitHub without repo permission yields 403s forever.

Do not paste PATs into HTML, skills, or commit messages. If the agent needs a token, it should read $GITHUB_TOKEN or ask you.

6. Skill so the agent does not re-read the homepage

Put a SKILL.md in the repo (this site uses skills/publish-site-artifact/SKILL.md) that restates llms.txt in agent-skill form. Then install it into local skill folders: 

curl -fsSL https://sites.arnavg.in/add-skill.sh | bash

That script is specific to this domain. For your own dump, copy add-skill.sh, change BASE_URL, SKILL, and the fetched SKILL.md so every rule names your owner/repo/host. Typical install locations:

  • ~/.agents/skills/ — Codex, Cursor, OpenCode, Pi, Copilot, Muse
  • ~/.claude/skills/ — Claude Code
  • ~/.grok/skills/ — Grok CLI
  • Grok on the web: a user skill under the session skills directory

ChatGPT / Claude custom GPTs that cannot install skills still work if you paste llms.txt into the project instructions and give them a GitHub tool.

7. How an agent publishes

Preferred: GitHub MCP / connector create_or_update_file

owner:   YOU
repo:    sites.yourname.tld
branch:  main
path:    learning/some-slug/index.html
content: raw HTML (not base64)
message: add some-slug

Fallback: gh, no clone

CONTENT=$(base64 < ./index.html | tr -d '\n')
gh api "repos/YOU/REPO/contents/learning/some-slug/index.html" \
  -X PUT -f message="add some-slug" -f branch="main" -f content="$CONTENT"

Updates must include the current blob sha from GET. Extra assets live in the same slug folder and are uploaded one file at a time.

8. Page rules worth enforcing

  • Self-contained HTML. Open the file in a browser with no server.
  • No frameworks, no build, no CDN you do not actually need.
  • No secrets, tokens, private keys, or other people’s personal data.
  • Slug from the title if the human did not pick one.
  • Default section: research/ unless they asked for a guide.

9. Check it works

  1. Push a dummy learning/hello/index.html yourself.
  2. Wait for Pages (often under a minute; TLS on a new domain takes longer).
  3. Open https://sites.yourname.tld/learning/hello/.
  4. Ask an agent: “publish a one-page guide to X on my sites dump.”
  5. Confirm the listing page gained a link (Action commit) and the public URL loads.
